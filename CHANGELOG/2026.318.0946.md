# 2026.318.0946 — feat(layer-buildkit)!: split the rootful builder out of layer-containerd

## Summary

The engine candy carried **one** packaged-only service (`buildkit.service`) beside a dual-venue one
(`containerd`, declared with both an `exec` and a `use_packaged` form). Because `plugin-box`'s
packaged-service lint reads the **candy**, that single entry marked the whole candy as dropped under
supervisord, so every image composition of it warned:

```
Warning: box "krun-host" includes candy ".../layer-containerd" with a packaged-only service
(no custom-exec sibling), but composition does not preserve_user (its systemd unit will be ignored)
```

The warning is true — the unit IS dropped in an image — but it names a candy whose pod-visible surface
was otherwise complete, and it blocked an unrelated pin PR (opencharly/distro-cachyos#164) on a
zero-warning gate that repo could not satisfy from its own tree.

**Why the concern moves rather than the rule.** `DESIGN.md` **D-CANDY-3** forbids a candy naming an
init system — *"A candy never names an init system … The init comes from the `os`"* — so a
per-service `host_only:`/`init:` marker is out, and a box-level acknowledgement would hide a real drop
instead of removing the mixed concern. Deleting buildkit is out too: this repo's bed asserts
`buildkit.service` is enabled AND active, and `CONTAINERD.md` §2 documents it as the host contract. So
`candy/layer-buildkit` now owns the rootful builder (its package and its packaged unit) and
`layer-containerd` is the engine alone. Precedent for two candies in one layer repo: `layer-cua`
holds five, `layer-omarchy-base` four.

**Two R1 findings fixed in this change, because the gate could not run without them:**

1. **The witness could not start at all.** `charly.yml` now composes the `vm:` substrate
   (`plugin-deploy-vm` import), because `check-containerd-vm` is a VM deploy and BringUpMembers
   dispatches `deploy add` for it. MEASURED on **unmodified main**: the bed failed at `[deploy-add]`
   after 1.0s with *"the vm deploy substrate is not available in this project — its deploy plugin
   (plugin-deploy-vm) is not in the candy closure"*. The gate had been red before this change; the
   pattern is the one the umbrella's own `charly.yml` records as charly#1083.
2. **`image/` was not ignored**, so the guest artifacts the bed writes showed up as untracked files —
   visible only once the bed could get past `deploy-add`.

## Change classification

**Breaking change + rollback:** a composition that relied on `layer-containerd` to install and enable
`buildkit.service` must now compose `layer-buildkit` as well — the engine keeps its package set, its
version-4 config, its seccomp profile and its plan unchanged, so nothing else moves, and the only
in-org composition (`krun-host`) needs no builder at all. Rollback is reverting this one commit: both
halves are additive candy declarations with no state migration, and the old candy re-enables the unit
on the next build.
